# Задачи — общая доска и календарь

Лёгкий аналог Trello для небольшой команды: канбан-доска + недельный календарь.
Работает прямо на GitHub Pages, а все данные (задачи и вложения) хранит в этом же
репозитории в отдельной ветке `tasks-data`. Никаких серверов и сторонних сервисов.

**Адрес приложения:** https://borinsobaka-lab.github.io/task-tracker/

## Возможности

- **Доска**: колонки, карточки, перетаскивание карточек и колонок.
- **Карточка**: название, описание с форматированием (жирный, списки, ссылки…),
  чек-лист, вложения-файлы, ответственные участники, срок с временем.
- **Календарь на неделю** (пн–вс), как в Google Календаре: задачи дня закреплены
  в шапке, их можно вытянуть в сетку и распределить по часам, двигать и растягивать.
  Задачи всех участников видны на одном календаре.
- **Синхронизация**: изменения сохраняются в GitHub автоматически, конфликтные
  правки двух человек аккуратно сливаются. Работает фоновое обновление.

## Вход по паролю

Вход защищён паролем, который задаёт владелец. Коллегам GitHub не нужен —
только адрес приложения и пароль.

**Первичная настройка (владелец, один раз):**

1. Создайте **приватный** репозиторий для задач: [github.com/new](https://github.com/new)
   → имя `task-tracker-data`, отметьте **Private** и **Add a README**.
2. Создайте [токен GitHub](https://github.com/settings/tokens/new?scopes=repo&description=Task%20Tracker)
   (галочка **repo** уже стоит) → **Generate token** → скопируйте `ghp_…`.
3. Откройте приложение → на экране «Настройка» вставьте токен и придумайте
   пароль → **Сохранить и войти**.

Токен шифруется вашим паролем (WebCrypto, AES-GCM + PBKDF2) и хранится в
зашифрованном виде в служебной ветке `app-config`. Без пароля расшифровать его
нельзя. Пароль нигде не сохраняется.

**Вход (все остальные):** открыть адрес приложения → ввести пароль. Сменить
пароль можно в «Настройки → Пароль и вход».

## Где лежат данные

- Приватный репозиторий `task-tracker-data`, ветка `tasks-data`: файл
  `board.json` (все задачи) и папка `attachments/` (файлы вложений).
- Каждое сохранение — это commit, поэтому у истории задач есть полный бэкап.
- Публичный репозиторий `task-tracker` содержит только код приложения и
  зашифрованный ключ доступа (`app-config/auth.json`) — данные там не лежат.

## Telegram-бот

Бот — **Cloudflare Worker** (`bot/worker/`, точка входа `worker.js`), крутится на
инфраструктуре Cloudflare (cron раз в минуту, без задержек). Делает две вещи:

**1. Групповые отчёты** в общий чат (`GROUP_CHAT_ID`):

- **10:00** (по `TZ_NAME`, у нас `Asia/Tbilisi`) — список задач на сегодня по
  каждому сотруднику со статусами (⬜ нужно сделать · 🔧 в работе · 👀 на
  проверке · ✅ готово; встречи — 📹).
- **днём** редактирует то же утреннее сообщение под текущие статусы — эмодзи
  обновляются при смене статуса, без новых сообщений.
- **20:00** — итог дня (сколько выполнено) и задачи на завтра.

**2. Личные уведомления** в личке бота: `/start` → пароль сервиса → выбор
участника → приходят «вам назначили задачу» и «через ~30 минут до задачи/встречи».

Статус берётся из роли колонки (меню колонки → «Статус для отчётов»).

**Настройка** (полная инструкция — `bot/worker/SETUP.md`):

- KV-хранилище `BOT_KV` (состояние диалогов/подписок/отчётов) и cron `* * * * *`;
- переменные: `GROUP_CHAT_ID` (id группы; узнать — команда `/id@ИмяБота` в группе),
  `TZ_NAME`, `MORNING` (`10:00`), `EVENING` (`20:00`), `DATA_*`, `AUTH_*`, `APP_URL`;
- секреты: `TELEGRAM_BOT_TOKEN` (от BotFather), `DATA_TOKEN` (доступ к приватному
  репозиторию данных), `WEBHOOK_SECRET`.
- @ник сотрудника для упоминания в отчёте — в настройках приложения, поле «Telegram @ник».

> Прежний бот на GitHub Actions (`bot/report.mjs` + `.github/workflows/telegram-bot.yml`)
> **выведен из эксплуатации**: расписание отключено, оставлен только ручной запуск
> для отладки. Актуальный бот — Cloudflare Worker выше.

## Разработка

```bash
npm install
npm run dev        # локальный запуск (http://localhost:5173/task-tracker/)
npm run build      # проверка типов + сборка в dist/
npm run test:e2e   # e2e-тесты Playwright (в демо-режиме, GitHub не нужен)
```

Демо-режим без GitHub: откройте приложение с параметром `?demo=1` — данные
будут храниться в localStorage браузера.

Публикация происходит автоматически: GitHub Actions собирает проект и выкладывает
его на GitHub Pages при каждом push (см. `.github/workflows/deploy.yml`).
